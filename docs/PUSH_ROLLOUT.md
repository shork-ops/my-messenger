# Фоновые push: состояние развёртывания

5 ноября 2026, проект nexus-messenger (wuifyiqnkpridblufxzs).

## Включено на сервере

- push-notify и push-dispatch развёрнуты из версии клиента PR #28; JWT шлюза отключён только для этих maintenance-функций, внутри проверяется отдельный PUSH_WEBHOOK_SECRET.
- Существующая пара VAPID сохранена. Публичный ключ опубликованного клиента совпал с серверным digest.
- Созданы PUSH_WEBHOOK_SECRET и соответствующие записи Vault nexus_project_url/nexus_push_webhook_secret. Значения не хранятся в репозитории и этом отчёте.
- Существующий on_message_insert_push заменён единственным webhook, передающим ID сообщения. Секрет читается из Vault; другие триггеры сохранены. Сбой HTTP-постановки не отменяет сообщение: остаётся durable queue.
- Cron nexus-push-dispatch активен раз в минуту. Существующая очистка исчезающих сообщений сохранена.

Повторяемая настройка webhook: supabase/setup/push-webhook.sql; планировщика: supabase/setup/push-cron.sql. Для последующих выкладок verify_jwt=false закреплён в конфигурации push-dispatch.

## Что проверено

- Без секрета и с неправильным секретом обе функции возвращают 401; правильный секрет позволяет worker обработать очередь.
- Два новых временных аккаунта прошли настоящий вход; обычное сообщение завершило обработку, отложенное оставалось без attempts до send_at и завершилось реальным Cron после send_at.
- Подписка тестового аккаунта автоматически получила session_id. Отзыв сеанса удалил её, а прежний JWT получил 42501 при обращении к проверке аккаунта.
- При завершении проверки очередь пуста, webhook ровно один, Cron active; последние HTTP-ответы pg_net — 200. Тестовые чаты, профили, пользователи и подписки удалены; исходные 8 подписок сохранены.
- Локально прошли 9 тестов Deno, проверки очереди и повторяемости webhook, сохранения сообщений при ошибке сети/конфигурации.

## Последний шаг на устройстве

Существующие 8 подписок ещё не привязаны к сеансам. На каждом нужном устройстве открыть https://shork-ops.github.io/my-messenger/, войти, нажать «Уведомления» и разрешить их в браузере. При уже выданном разрешении приложение повторно зарегистрирует подписку. Затем закрыть вкладку и получить сообщение от другого аккаунта; отдельно проверить scheduled-сообщение.

В изолированном тестовом Chromium push-служба отказала в регистрации (AbortError). Поэтому провайдерская доставка и появление системного уведомления на пользовательском устройстве этим запуском не подтверждены. Успех обработки задания без подходящей подписки не означает доставку до устройства.

Отложенное уведомление запускается ближайшим минутным Cron; batch — 10 заданий. Очередь повторяет ошибки, но сохраняется аварийное окно возможного дубля после принятия push провайдером до записи квитанции.
